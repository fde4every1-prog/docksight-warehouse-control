1. Order Application

Orders are coming from a UI screen currently; instead make it a seperate application (Name it: FDE Bazaar) outside this Control Tower application. Connect the Orders application to Warehouse Control Tower application using APIs.

Each new order should trigger API in control tower

Application can have multiple SKUs in a single order. Generate a order ID and include the record in the order database. Provide order service (Next_Day, Same_Day, Standard).

2. Order Acceptance - Warehouse Mapping & Order Queue Entry (Planning should be done for each SKU in the order)

API trigger from order application parses the order maps the SKU to the warehouse based on quantity and availabaility using the "inventory_snapshot" database table

Select the warehouse if the minimum of (wms_qty, erp_qty, vision_qty) minus reserved_qty is greater than or equal to the  order quantity.

Based on warehouse and zoning, the orders are split into multiple items in the queue - a new table (sub-orders table) is to be created -- which includes all items/SKUs in the order and the cut-off time, this table is updated whenever an item is low in stock and the order is put on hold. Each item in the queue is assigned a cut-off time for fulfillment which is later used to prioitize the workload.

Standard	OrderTime+24 hrs
Next Day	OrderTime+12 hrs
Same Day	OrderTime+6 hrs

Any order can be partially fulfilled as in to proceed with order fullfillment for available SKUs and put rest of the SKUs on hold.


3. Order Fulfillment - Fleet Task Assignment

Once warehouse is selected, items are listed in the sub-orders table. Fleet Management System automatically assigns tasks to robots and assets for (Pick, Move, Pack_feed, Stage). It should only consider robots & assets that are 
 - fit to use in the Fleet Management System.

For robots only consider robots that are good to use based on below rules -
    Robots.csv HEALTH_STATUS = "HEALTHY"; safety_cert_status <> 'EXPIRED'; connectivity = ('INTERMITTENT','ONLINE') 
    maintenance.csv 'cmms_status' <> ('OPEN','IN_PROGRESS'} and fleet_availability = 'AVAILABLE'
    robot payload capacity against the sku weight
    Battery status > 10%

For control_assets.csv consider assets that are good to use based on below rules -
    state = "AVAILABLE" and maintenance_state = "CLEAR"

For now let's continue to use 45 seconds as standard task completion for each assigned task to robots/assets.
